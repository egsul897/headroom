# Headroom — working agreements

## Reporting

Always deliver mission reports inside a fenced code block, ready to copy and paste.

- Every numbered required-return list, every final report, every verdict write-up.
- Use a four-backtick fence so inner markdown (tables, headings, quotes, inner fences)
  survives intact.
- When a mission produces more than one report — for example a required return AND a
  narrative final report — box each of them separately, each under its own heading.
- Box the report even when the same content was just written to a file in `docs/`.
  The on-disk artifact is the record; the boxed copy is the deliverable.
- Keep short conversational replies (a status line, a question, a one-line confirmation)
  outside the box. The box is for reports, not for chat.
