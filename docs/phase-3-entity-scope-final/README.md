# Phase 3 final blocker: entity-scope consistency guard

Starting SHA `995bed37dcc6d1111cec59c966f1d7e1321e71aa`. Zero paid, model or provider calls. No new compile of any agreement.
Generated by `scripts/phase-3-entity-scope-final.ts` (frozen-IR replay + synthetic cases + regression inputs).

## What was wrong

The closure synthesis at the starting SHA left one blocking invariant: authoritative `entityScope` under-inclusion.
Rules whose own source binds the Borrowers and their Restricted Subsidiaries carried `entityScope ["BORROWER"]`,
two of them COMPLETE, with no limitation stated. Two independent deterministic gaps allowed that:

- **A. silent drop.** The normalizer mapped every wire entity tag through `matchEnum` and filtered out unrecognized
  values with no warning, no sufficiency change and no record of the raw value (rule fields and
  ENTITY_SCOPE_REFERENCE nodes alike).
- **B. no source-consistency guard.** Nothing compared the normalized scope with the binding language of the rule's
  own excerpt or of the lead-in of the unit it cites.

The raw wire output of the frozen run was not persisted (neither the compile result nor the durable shard records
carry it), so which of the two caused the observed run is unknowable. The fix covers both.

## What changed (production)

- `lib/contract-model/compiler/semantic/entity-scope-guard.ts` (new): tag classification with exactly one outcome per
  emitted tag (RECOGNIZED / UNRECOGNIZED, aliases only to exact enum classes), the generic source-binding vocabulary
  mapped onto a five-atom lattice, deterministic cited-unit lead-in extraction, and the guard itself.
- `lib/contract-model/compiler/semantic/normalize.ts`: rule fields and ENTITY_SCOPE_REFERENCE nodes go through the
  classifier (unrecognized tag = warning + audit + non-authoritative scope + PARTIAL); the guard runs on every rule
  right after normalized composition against the rule's own excerpt AND the lead-in of its cited unit.
- `lib/contract-model/ir/types.ts`: additive optional `IRRule.entityScopeAudit` (status, safeToRely, reason codes,
  raw emitted wire values, tag normalization records, before-state, witness and signals).

Safety direction: remove false precision, never invent it. Under-inclusive or unrecognized scope becomes unspecified
(`[]`) and the rule is limited (COMPLETE becomes PARTIAL) with a machine-readable reason
(`ENTITY_SCOPE_UNDERINCLUSIVE_VS_SOURCE`, `ENTITY_SCOPE_UNRECOGNIZED_TAG`). A scope is never widened by guess. A scope
with no binding language in any bound text is left untouched but marked `safeToRely=false` (UNWITNESSED).

## Frozen replay result

Of the 17 rules that carried a non-empty scope: 5 are UNDERINCLUSIVE_VS_SOURCE and become unspecified + PARTIAL
(2 of them were COMPLETE, 3 were already PARTIAL and gain the scope reason), 3 are SOURCE_MATCH_CONFIRMED and unchanged,
9 are UNWITNESSED and unchanged with `safeToRely=false`. The 46 empty scopes are UNSPECIFIED. No scope was widened.
The blocking finding's seven rules end as: five explicitly limited, one with no scope claim, one unwitnessed and
PARTIAL. The verifier is untouched; its warning may recur on a future run but no longer names a confident
authoritative error.
