# P2 — Production integration notes (Position / Simulate / Ask)

## Architecture rule

Do **not** rebuild a second rule engine. Activated covenant rules flow through:

1. Counsel compile → `Permission` / `CovenantProvision` (existing interface)
2. Legacy Position/Simulate path for MODELED UNVERIFIED customer work-in-progress
3. Phase-3 CERTIFIED → Phase-4A/4C/4D for verified execution architecture

## Cross-document / PSA agents

| Surface | Must receive | Must not claim |
|---|---|---|
| Position | Modeling + review status; utilization status | CERTIFIED permission from DISCOVERED summary |
| Simulate | Explicit financials; attributed usage when shared | Silent zero usage as empty basket |
| Ask | CapacityAuthority + maturity labels | Legacy favorable output as legal certification |
| Cross-document | Amendment graph / operative identity | Merging amendment text into certified IR without seal |

## Legacy vs certified

- Legacy engine clear/blocked is a **calculation outcome**, not certified legal permission.
- Phase-4D simulation over CERTIFIED IR is the verified execution path.
- UI must keep these labels distinct when activated Neon rules appear.

## This cycle

Activation matrix + E2E proofs exercise the counsel compile and legacy evaluate/simulate path only, with ephemeral companies. No uncontrolled production Neon promotion.
